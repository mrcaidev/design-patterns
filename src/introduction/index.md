# Introduction

Welcome to yet another website that tries to help humans understand design patterns. 😀

Here I put my scattered thoughts and opinions about various design patterns, mostly GoF ones.

As I myself mostly do web development, I implement all design patterns in [TypeScript](https://typescriptlang.org/). Lucky for you if you are also a web dev guy! 😎 But no worries if you come from Java or C#, because TypeScript is quite similar to them in terms of basic syntax and structure.

And I wrote two versions for each pattern: one is written under the classic **OOP** paradigm, which is pretty much the same as you would have seen on other websites. The other one is written under **FP** paradigm, which can sometimes look very different from the OOP one, while they actually share the same core concept. I hope you would find the contrast interesting, or even inspiring.

This website may not contain the most formal and accurate definition, nor does it have a comprehensive guide of when, why or how you should use them. If you are looking for that, I guess you might as well grab a book, or check out the super awesome [Refactoring Guru](https://refactoring.guru/design-patterns) website - which is where I myself, as a beginner, get to know about design patterns.

Do please feel free to correct me, if you find any mistakes or have any suggestions. I would be very grateful for that. You can do that by [opening an issue](https://github.com/mrcaidev/design-patterns/issues) on GitHub, or click on that "Edit this page" link at the bottom of each page to make a pull request. We learn by sharing and discussing. 🤝

Happy reading!
